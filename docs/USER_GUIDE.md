# Math IM Book 完整使用教程

本文从第一次打开页面开始，介绍 Math IM Book 的主要操作、推荐工作流、数据管理和可选高级配置。安装尚未完成时，请先阅读[跨平台安装与部署指南](INSTALLATION.md)。

## 1. 先理解工作区

Math IM Book 不是普通聊天页面，也不是传统笔记软件。它围绕一个循环工作：

```text
提出数学问题 → 继续追问或建立分支 → 识别值得保留的知识 → 生成知识笔记 → 在后续问题中复用
```

桌面端界面主要分为三部分：

1. 左侧导航：在 `Conversations` 和 `Library` 之间切换，搜索、整理对话与知识笔记，进入全局设置。
2. 中间工作区：阅读对话、提问、选择模型与回答风格，查看回答的处理细节。
3. 右侧阅读器：打开知识笔记，查看正文、符号表和相关概念；没有打开笔记时不会显示。

窄屏设备会把左侧导航折叠为菜单。界面文字目前以英文为主，但提问和笔记内容可以正常使用中文。

## 2. 首次配置模型服务

没有模型服务配置时，页面可以打开和浏览本地内容，但不能正常生成回答。

### 2.1 打开全局设置

点击左侧栏底部的齿轮按钮 `Global Settings`。设置窗口分为供应商配置和 `Default Options` 两部分。

### 2.2 选择供应商

内置目录包含：

| 供应商 | 接口类型 | Base URL |
| --- | --- | --- |
| Gemini | Google Gemini SDK | 无需填写 |
| DeepSeek | OpenAI 兼容 | 默认 `https://api.deepseek.com/v1` |
| OpenRouter | OpenAI 兼容 | 默认 `https://openrouter.ai/api/v1` |
| GLM | OpenAI 兼容 | 默认 `https://open.bigmodel.cn/api/paas/v4` |

点击一个供应商后：

1. 在 `API Key` 输入从供应商获得的密钥。
2. 检查 `Models` 列表，选择其中一个默认模型。
3. 需要其他模型时，在 `Enter model id` 输入供应商实际支持的模型 ID，然后点击 `Add`。
4. 对 OpenAI 兼容供应商检查 `Base URL`。这里只填接口根地址，不要填具体的聊天完成路径。
5. 点击 `Save Provider Config`。

模型 ID 和 Base URL 必须与供应商实际接口一致。内置列表是便于首次配置的默认值，并不保证供应商以后不会调整型号或下线模型。

已经保存过供应商时，API Key 输入框保持空白表示沿用原密钥；只有输入新值并保存才会替换密钥。

### 2.3 设置默认选项

进入左侧的 `Default Options`：

- `Default Conversation Model`：新对话默认用于回答问题的模型。
- `Utility Model`：用于生成会话标题、数学分类等辅助任务的模型；个人使用可以与会话模型选择同一个。
- `Markdown Theme`：回答和知识笔记的排版主题。
  - `Academic`：严肃学术排版。
  - `Reading`：更柔和的长文阅读风格。
  - `Geek`：更接近工程文档的风格。

点击 `Save Default Options`。下拉框只显示已经配置过的供应商和模型；为空时先返回供应商页面完成保存。

### 2.4 密钥保存在哪里

供应商设置保存在：

```text
data/credentials/credentials.json
```

API Key 不会通过凭据列表 API 返回到页面，但文件本身是明文。不要提交这个文件、分享包含它的备份，或让不受信任用户访问运行主机。

## 3. 创建第一次对话

### 3.1 新建问题

在 `Conversations` 页面可以用任一方式开始：

- 直接在空白工作区底部输入问题。
- 点击左侧 `Conversations` 标题旁的 `+`，选择 `New inquiry`。
- 光标不在输入框时按 `N`。
- 点击空白页的示例问题，把模板填入输入框后继续修改。

输入框中：

- `Enter` 发送。
- `Shift+Enter` 换行。

第一次提问后，系统会保存会话、生成简短标题，并自动选择一个数学分类图标。

### 3.2 选择教学策略

新对话第一次发送前，输入框下方可以选择策略：

- `Top Down`：先给整体结构，再逐步展开，适合学习新主题。
- `Raw`：尽量少做额外组织，直接按原问题回答。

策略属于会话级设置，只在新对话时选择。对话开始后保持一致，避免连续追问时讲解方法突然变化。

### 3.3 选择回答风格

每次发送前都可以选择回答风格：

- `Natural response`：不附加额外风格限制。
- `Concise`：尽量简洁但保持完整。
- `Step by Step`：编号列出中间步骤。
- `Intuitive`：优先直觉、例子和整体图景。
- `Rigorous`：优先严格定义与推导。

回答风格是单轮选择，可以在同一会话中按问题改变。例如先用 `Intuitive` 建立直觉，再用 `Rigorous` 检查证明。

### 3.4 写出更有效的数学问题

模型在边界清楚时更容易给出可复用回答。推荐同时说明：

- 目标：要理解、证明、计算、检查还是找反例。
- 已知条件：定义域、假设、采用的记号。
- 当前水平：希望使用哪些定理，哪些还没有学过。
- 输出偏好：直觉、严格证明、具体例子或逐步推导。

示例：

```text
我学过群和线性代数，但还没有学过模论。请先用表示矩阵解释舒尔引理的直觉，
再给出有限维复表示情形的严格证明，并指出不可约性在哪一步使用。
```

## 4. 在对话中工作

### 4.1 连续追问

在同一会话继续输入时，系统会结合会话历史和相关知识节点回答。适合围绕同一目标逐步澄清、补证明或修正推导。

问题已经明显转向另一个主题时，建议新建对话；如果新问题源自某个具体回答，优先使用分支。

### 4.2 切换会话模型

点击工作区右上角的调节按钮 `Conversation Model`，从已配置模型中选择并保存。

- 新对话中选择模型，只影响即将创建的会话。
- 已存在会话中保存模型，会更新该会话后续请求使用的模型。
- 这里只能选择已经在全局设置中配置过的模型。

### 4.3 回答操作

每条助手回答底部可能出现：

- `Fork`：从这条回答创建新的对话分支。
- `Copy`：复制回答的 Markdown 原文。
- `Retry`：重新生成最后一条助手回答；为避免重写中间历史，只在最新回答显示。

### 4.4 什么时候使用分支

分支适用于“不想污染当前思路，但需要沿某个中间结果深入”的情况，例如：

- 主线正在证明定理，想暂时补一个定义。
- 同一个结论要比较两种证明。
- 想从回答中的某个假设出发研究反例。

点击目标回答的 `Fork` 后会进入子会话。子会话保留可追溯的父分支锚点，而不是复制一份可以随意改写的历史。左侧对话树会显示分支关系。

删除会话时，如果它仍有子分支，后端会拒绝删除父会话；应先处理子分支。

### 4.5 查看回答处理细节

回答中出现 `View details` 时，点击可进入 `How this response was made` 页面。这里可能显示：

- 本轮采用的处理路径、意图和知识保存决策。
- 候选知识笔记及其生成状态。
- 本轮使用的活动知识节点、摘要节点和记忆范围。
- 待处理、失败的知识任务和符号冲突数量。
- 最近几轮的决策记录。

这些信息用于理解系统为什么保存或没有保存某段内容，也便于排查上下文与知识生成问题。点击页面顶部返回按钮回到对话。

## 5. 把内容沉淀为知识

知识笔记是独立的 Markdown 文件，不等同于聊天记录。它们可以被后续回答引用，也可以在 `Library` 中长期整理。

### 5.1 从回答建议生成笔记

系统可能在回答细节中列出候选笔记。进入 `View details` 后：

1. 查看 `Keep the useful parts` 区域。
2. 勾选真正值得长期保留的条目。
3. 点击 `Create N`。
4. 等待状态从 `Queued` / `Creating` 变为 `Saved`。

生成完成后，回答卡片会出现 `Saved ideas` 链接；点击即可在右侧阅读器打开对应笔记。

不要把每段回答都保存。优先保留定义、关键定理、可复用证明结构、稳定的直觉解释和典型反例，知识库会更清晰。

### 5.2 划词继续问

在聊天回答或知识笔记正文中选中一段文字，然后按：

- Windows / Linux：`Ctrl+Q`
- macOS：`Command+Q`

浮动菜单选择 `继续问`，再选择：

- `怎么理解`
- `形象解释`
- `具体说明`

系统会把所选原文按引用格式填入问题输入框，你可以继续编辑后再发送。从知识笔记划词继续问时，会先创建一个新对话，避免阅读动作意外改变已有会话上下文。

### 5.3 划词生成知识节点

选择文字并按 `Ctrl+Q` / `Command+Q`，切换到 `知识节点`，可直接请求生成：

- `定义`
- `形象解释`
- `应用例子`
- `证明`

任务在后台编译，完成后会打开新笔记或在知识库中出现。生成过程依赖当前选择的会话模型。

### 5.4 公式选择和复制

页面显示公式时，浏览器中看到的是 KaTeX 排版结果。项目会尽量在选择、复制和划词提问时恢复原始 LaTeX，而不是复制成零散的视觉字符。这对继续推导和保存公式非常重要。

## 6. 使用知识库

### 6.1 打开知识笔记

可以从两个入口打开：

- 点击回答中的 `Saved ideas`。
- 切换左侧 `Library`，点击知识条目。

笔记在右侧阅读器显示。阅读器顶部可以扩大宽度、恢复预览宽度或关闭。

### 6.2 阅读笔记内容

一篇笔记可能包含：

- 标题、类型和摘要。
- Markdown 正文与数学公式。
- `Symbol Registry`：该笔记涉及的符号及含义。
- `Related concepts`：当前笔记依赖的概念，以及引用当前笔记的其他概念。

点击相关概念卡片可以在阅读器中继续导航，不会强制切换当前对话。

### 6.3 自动整理知识库

点击 `Library` 标题旁的 `+`，选择 `Organize Library`，系统会根据当前知识条目的类型把它们放入定义、定理、证明、例子或通用概念文件夹。已经由用户手动移动并锁定位置的条目会优先保留用户选择。

知识少时无需频繁自动整理；积累一批笔记后集中整理更有意义。

## 7. 整理对话与知识

`Conversations` 和 `Library` 使用相同的文件树操作。

### 7.1 搜索

在左侧搜索框输入标题、摘要、类型或路径中的文字。搜索时匹配的文件夹会自动展开。搜索框为空时显示 `/` 提示；光标不在输入控件内时按 `/` 可快速聚焦搜索。

### 7.2 新建文件夹

点击当前区域标题旁的 `+`，选择 `New folder`。如果先选中了某个文件夹，新文件夹会创建在该位置下。

在 `Conversations` 中选择一个文件夹后再新建问题，新会话会进入当前文件夹。

### 7.3 移动条目

有两种方式：

- 直接把对话或知识条目拖到目标文件夹。
- 点击条目右侧的 `…`，选择 `Move to…`。

拖到顶层标题区域可以移回顶层。

### 7.4 重命名、图标和删除

- 点击条目右侧 `…` 可以移动、重命名或删除。
- 点击条目前面的数学分类图标可以更换分类。
- 文件夹右侧 `…` 可以重命名或删除空文件夹。
- 非空文件夹不能直接删除，需要先移动其中的条目和子文件夹。
- 删除对话是永久操作，重要内容应先备份。

## 8. 推荐工作流

一个适合个人数学学习的轻量流程：

1. 按课程、教材或研究主题建立少量对话文件夹。
2. 新主题用 `Top Down + Intuitive` 建立整体图景。
3. 关键结论改用 `Rigorous` 或 `Step by Step` 检查细节。
4. 偏离主线的疑问使用 `Fork`，不要在同一个会话无限跳题。
5. 只保存后续可能复用的定义、定理、证明方法和典型例子。
6. 从知识笔记划词继续问，修补真正不清楚的部分。
7. 每积累一批笔记，再整理文件夹和概念关联。
8. 定期备份 `data/`。

## 9. 数据文件与迁移

| 路径 | 内容 | 是否包含敏感信息 |
| --- | --- | --- |
| `data/credentials/credentials.json` | API Key、Base URL、供应商模型列表 | 是 |
| `data/chats/sessions/` | 会话元数据、消息和分支信息 | 可能包含个人内容 |
| `data/chats/sessions_index.json` | 会话列表索引 | 可能包含标题和摘要 |
| `data/knowledge/*.md` | 知识笔记 | 取决于内容 |
| `data/explorer/index.json` | 文件夹、条目位置、图标 | 可能含个人分类信息 |
| `data/config/` | 默认模型选项、回答风格、教学策略 | 通常不含密钥 |

迁移到另一台电脑时：

1. 在旧电脑停止应用。
2. 备份整个 `data/`。
3. 在新电脑完成项目安装。
4. 停止新电脑上的应用。
5. 用备份替换新项目的 `data/`。
6. 重新启动并检查供应商配置、对话和知识库。

不同操作系统之间可以直接迁移这些 UTF-8 JSON 和 Markdown 文件。

## 10. 清理历史

需要清空全部对话和生成知识时，先备份并停止应用，再从项目根目录执行：

Linux / macOS：

```bash
.venv/bin/python scripts/clear_history.py
```

Windows：

```powershell
.\.venv\Scripts\python.exe scripts\clear_history.py
```

脚本会删除 `data/chats/sessions/` 和 `data/knowledge/` 下的内容，并把会话索引重置为空。它不会删除供应商 API Key、默认模型、回答风格和教学策略。

## 11. 高级定制

下面的配置适合愿意直接编辑 JSON 或 Markdown 的用户。修改前先备份，JSON 必须保持合法语法；应用运行中修改后通常刷新页面或重启即可生效。

### 11.1 自定义回答风格

回答风格目录：

```text
data/config/answer_styles/
```

新增风格时：

1. 在 `index.json` 的 `styles` 数组增加唯一 `style_id`、显示名称和描述。
2. 创建同名 Markdown 文件，例如 `visual.md`。
3. 在 Markdown 文件中写只针对输出风格的增量指令。

不要把完整系统提示重复写入每个风格文件。`default` 表示不添加额外覆盖。

### 11.2 自定义教学策略

教学策略目录：

```text
data/config/strategy_agents/
```

在 `index.json` 添加策略元数据，并创建与 `strategy_agent_id` 同名的 Markdown 文件。策略负责组织整段会话的讲解方式，应该比单轮回答风格更稳定。

### 11.3 自定义用户背景

可以手动创建：

```text
data/config/USER.md
```

写入希望模型长期了解的稳定背景，例如：

```markdown
# User Profile

- 已学过线性代数、实分析和基础群论。
- 偏好先讲直觉，再给严格定义。
- 未特别说明时，证明可以使用本科高年级的标准结论。
```

该内容会加入规划和回答上下文。只写稳定、确实有帮助的信息；不要放入密码、API Key 或不希望发送给模型服务的隐私。

### 11.4 修改供应商目录

供应商、模型初始列表和默认选项位于：

```text
data/config/provider_options.json
```

普通用户优先通过页面添加模型。只有需要新增供应商入口、修改预置模型或修复默认 Base URL 时才直接编辑此文件。API Key 不应写入这里。

## 12. 故障排查

### 发送后提示检查供应商设置

确认 API Key、模型 ID、Base URL 和默认会话模型都属于同一份已保存配置。查看启动终端可以区分认证失败、限流和上游服务错误。

### 回答正常，但标题分类不理想

标题和分类由 `Utility Model` 生成，失败时会退回到问题原文和通用分类。可以在全局设置中选择更稳定或更便宜的辅助模型，也可以在左侧手动重命名和更换分类图标。

### 知识笔记长时间处于生成中

知识任务当前在应用进程内执行。保持应用运行并等待页面轮询；如果进程重启，未完成的内存任务不会自动恢复。可以重新从回答细节或划词菜单发起生成。

### 划词菜单没有出现

确认选择范围完全位于同一条聊天消息正文或同一篇知识笔记正文内，然后按 `Ctrl+Q` / `Command+Q`。标题、按钮、侧栏和跨多个内容区的选择不会触发菜单。

### 公式复制结果不正确

尽量只选择一个完整公式或连续正文。跨多个公式容器、标题和正文的混合选择可能无法完整恢复 LaTeX，可以改用回答的 `Copy` 获取整段 Markdown。

### 知识库或对话树出现旧位置

先刷新页面。仍存在问题时检查 `data/explorer/index.json` 是否可写、是否为合法 JSON，并确认运行用户拥有 `data/` 的读写权限。

### 页面布局或脚本更新后没有变化

停止应用，重新运行 `setup.sh` / `setup.bat` 构建前端，再启动。浏览器仍缓存旧资源时执行强制刷新。
