# 主要交互流程
用户问一个问题，可能是比较宽泛的问题，或者一个很具体的问题，先从抽象层次的去简要讲解下，一个形象高层次点的理解，不要过长，也不要过短过长了的话，就是内容太复杂了，太详细了，不是不适合那种由简入深，由抽象到具体的过程。太简单的话，就是说会频繁地询问，这也是很体验不好。
具体的定义，一些详细的东西的话，会做到markdown文件的知识点里面，用户去具体去点击知识点或者是去详细询问才会实际生成并落盘

希望把落盘的未落盘的markdown文件知识点按照书籍的逻辑自动组织好，agent需要自己管理这部分
agent可能需要知道目前所有的markdown的list的摘要，部分还需要load到具体内容

对话中会引用到 markdown文件，markdown文件也会关联到一些chat list

## 整体结构，左中右三栏：
- 左栏：知识与会话导航
- 中栏：当前对话链
- 右栏：Markdown 渲染与引用面板

这样用户的心智会很清晰：
左边找书和章节，中间生产内容，右边看结果和引用关系。

一、左侧边栏设计建议

直接拆成上下两个区域。

上半部分：Chat Chain / Fork Tree

fork是一个小按钮，放在每一个AI的回答下面，由用户自己决定是否fork，
fork的好处是不会继承非这一支的上下文
需要记录每一分支的摘要信息，创建时间，对话数

支持把某个 fork 标记为“主线”，即展开对话列表

fork其实也很适合目录树那种形式，
这部分就放对话列表吧，支持创建新的对话(就是从根节点fork)

下半部分：书籍目录树

结构类似 VSCode Explorer

支持 章 > 节 > 小节  （由于是对话产生不一定要严格按照书籍的组织方式，足够层次化就行）
每个节点显示状态：
未生成
已生成

记录一些信息，比如引用到的chat list

点击某个章节，自动切换到该章节对应的Markdown文件 + 对话 list



- 树状的层次也可折叠
